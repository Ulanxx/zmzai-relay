# 中转驿渠道编辑

**状态：** 已确认，待实施计划  
**日期：** 2026-08-06  
**范围：** `zmzai-relay` Admin 渠道资源的更新与停用。

## 目标

让运营人员在 `/admin/channels` 连续完成渠道查看、编辑、启停和连通性测试。Token 继续只管理调用权限、限流与额度；Token 不绑定渠道，网关依照模型映射、启用状态与优先级选择渠道并故障切换。

## 交互

每个渠道行提供“编辑”和“测试”。选择编辑后，在同页的渠道表单中载入该渠道的公开配置：名称、Base URL、模型映射、优先级、输入/输出成本、超时和启用状态。

上游 Key 永不返回浏览器，也不显示是否为空。编辑表单中的 Key 字段为空时保持数据库内原值；仅当管理员填写新值才替换。保存成功后更新列表内该行并退出编辑状态。渠道停用后不参与新请求路由，既有调用、账本与渠道尝试记录不改写。

不提供永久删除。停用是可恢复操作，也保留完整运营与账务追溯。

## 接口

新增 `PATCH /api/admin/channels/:id`，要求管理员会话。

- 接受完整的公开配置：名称、地址、模型映射、优先级、两项成本、启用状态和超时；`apiKey` 可选；
- `PATCH` 采用表单提交的完整替换语义：所有公开配置字段均必填，空请求、缺失字段和未知字段均返回 `400`，避免默认值意外覆盖既有配置；
- 空白或未提供的 `apiKey` 不进入更新；
- 目标不存在返回 `404`，格式错误返回 `400`；
- 响应始终剔除 `apiKey`。

创建和更新共用同一严格校验：两项成本必须同时为 `null`（成本待配置），或同时为非负整数；`0` 仅表示确认免费，不能由省略字段隐式产生。

渠道地址只能使用 HTTPS 公网地址。每次保存、渠道测试和实际网关转发前，服务端都解析主机名的全部 IPv4/IPv6 结果，拒绝回环、私网、链路本地、保留地址及无法解析的主机。出站连接必须使用刚刚校验过的地址而非重新由系统解析域名，以阻断 DNS 重绑定；同时保留原主机名作 TLS SNI 与证书校验。请求不跟随重定向。旧渠道也经过同一出站检查，不符合策略时被跳过并记录失败原因。这样编辑渠道不会让上游 Key 被转发到内网目标。

## 验收

- Admin 可修改并保存渠道公开配置；
- 留空上游 Key 后保存，原 Key 仍可通过渠道测试；
- 填写新 Key 后保存，只有新 Key 被用于后续测试与转发；
- 停用渠道后网关不再把它作为候选渠道；
- Token 创建页不出现渠道选择，仍由网关按优先级路由。
