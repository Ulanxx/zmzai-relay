# 中转驿完整工作面与 5.6 模型目录

**状态：** 已确认，待实施计划  
**日期：** 2026-08-06  
**范围：** `zmzai-relay` 的 Admin、User 页面、页面查询 API 与模型配置迁移。

## 目标

将中转驿由分散的演示页面收敛为两套连贯工作面：

- Admin 完成模型、渠道、用户、余额、Token、调用与账本的运营闭环；
- User 完成余额、Token、用量、账单和 API 调用的使用闭环；
- 对外只公开真实的 gpt-5.6 模型，推理强度作为请求参数而非伪模型名。

本规格建立在既有账务、预授权、故障切换与 SSO 设计之上，不改变其结算语义。

## 模型目录

对外模型与 viva 上游同名直连：

| 公开模型 | 上游模型 |
| --- | --- |
| `gpt-5.6-sol` | `gpt-5.6-sol` |
| `gpt-5.6-terra` | `gpt-5.6-terra` |
| `gpt-5.6-luna` | `gpt-5.6-luna` |

`gpt-4o` 从渠道映射中移除；其 `ModelPrice` 记录只设为停用，历史 Usage 与账本绝不改写。

调用可传 `reasoning_effort`，仅允许 `low`、`medium`、`high`、`xhigh`，网关验证后直接透传上游。它不是模型别名。没有配置实际渠道成本的模型必须在 Admin 显示“成本待配置”，并且不能把零成本当作确认毛利。

## Admin 工作面

Admin 使用一套固定侧栏和共享页头：

1. **概览**：时间范围内的收入、确认成本、待核查成本、毛利、成功率、渠道健康、异常与未结算调用。
2. **模型目录**：管理 Sol/Terra/Luna 的公开状态、输入输出价格、上下文上限、渠道映射与可用推理强度。
3. **渠道**：管理上游地址、模型映射、双向成本、优先级、超时、启停与连通性测试。
4. **用户与余额**：搜索用户，查看余额、消费、Token、最近调用；加减余额必须填写理由并写审计。
5. **调用与账本**：以同一筛选器查看调用、余额流水、失败与未结算项。调用行可展开显示 requestId、渠道、推理强度、tokens、收费与错误。
6. **Token**：跨用户查找、吊销与检查 Token；它补充用户详情，但不创建另一套导航。

Admin 写操作在当前页完成后保留筛选状态并显示结果；上游 key 永不返回浏览器。

## User 工作面

User 使用顶部导航：

1. **概览**：可用余额、本月消费、调用量、成功率、最近调用和低余额提示。
2. **我的 Token**：创建、模型权限、每分钟限流、月消费上限、吊销与轮换。明文只在新建或轮换响应中显示一次。
3. **用量与账单**：调用和余额流水分栏，可按模型、Token、状态、时间筛选；调用行可展开查看结算详情。
4. **调用文档**：显示仅有的三个 5.6 模型、允许的 reasoning effort 与可复制的请求示例。

User 查询一律以当前 session user id 限定；不展示渠道、渠道成本、毛利或其他用户数据。

## 页面与路由迁移

Admin 资源页共享同一壳层。既有 `/admin/channels` 与 `/admin/keys` 必须保持可达并重定向至新工作面相应区域，旧书签不失效。

现有 `/dashboard` 拆为 User 工作面的默认概览。Token、用量、账单和文档拥有独立页面，不再在一个长页混杂操作、说明和记录。

页面查询由服务端聚合层提供：

- Admin 概览聚合时间范围内的业务与健康指标；
- 用户运营查询聚合指定用户的余额、Token、消费与调用；
- User 工作台查询只读取当前用户的账户、Token、调用、账本与开放模型。

金额、成本、毛利、权限和可用模型均由服务端返回；浏览器不计算财务值。

## 验收

- Admin 可从概览连续进入模型、渠道、用户与账本，并完成调价、余额调整和调用核查；
- User 可管理 Token，查看同一模型目录下的调用文档、用量与账单；
- Sol、Terra、Luna 均能实际调用，至少一条流式请求使用 `reasoning_effort=high`；
- 旧 gpt-4o 调用保留可追溯历史，新请求不可再选它；
- 桌面与移动导航、表格、抽屉和操作面板不溢出。
