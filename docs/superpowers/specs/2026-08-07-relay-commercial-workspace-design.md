# 中转驿商业化工作面设计

**状态：** 已确认，待实施计划  
**日期：** 2026-08-07  
**范围：** Relay 首页、用户工作面、管理员工作面与核心模型目录体验。

## 产品判断

中转驿不是供应商市场，也不展示虚假的模型数量。当前只有 Sol、Terra、Luna 三个真实模型，因此首页的第一任务是让个人开发者比较模型和价格，第二任务才是登录、创建 Token 和开始调用。

从 OpenRouter 借鉴产品闭环，不复制视觉：公开模型目录、模型详情、可复制调用示例、统一 API Key、用量和账单必须互相连通。

## 路由行为

`/` 是智能入口：

- 未登录：展示公开模型目录型落地页；
- 已登录普通用户：直接进入 `/dashboard`；
- 已登录管理员：直接进入 `/admin`。

未登录用户可以浏览模型、价格和 API 文档摘要；创建 Token、查看个人余额、调用 API 时跳转统一 SSO 登录。管理员可以从管理工作面切换到用户工作面。公开路由为 `/models`、`/models/[model]` 和 `/docs`；首页模型行链接到对应详情页，顶部 API 文档链接到 `/docs`。

## 未登录首页

首页采用 Hallmark Catalogue 结构：模型是主内容，不使用静态口号作为唯一首屏。

- 顶部：`zmzai cloud · 中转驿` wordmark、模型目录、API 文档、右上角登录；
- 首屏标题：说明统一模型接入，不承诺虚构性能指标；
- 模型目录：Sol、Terra、Luna 等宽列表，显示输入/输出价格、上下文上限、最大输出、推理强度和可用状态；
- 行为：查看模型详情、复制请求示例、开始使用；需要个人操作时再触发登录；
- 底部：牧之署名、产品矩阵入口、API 规范与服务状态链接。

模型目录数据由服务端读取启用的 `ModelPrice` 与启用渠道映射。只有 `price.enabled && exists(enabled channel mapping)` 的模型才标为“可用”；没有可路由渠道的模型明确显示“暂不可调用”。价格和能力不由浏览器计算。不存在真实数据的指标使用“待配置”或破折号，不编造可用率、延迟和用户数量。

公开页面只暴露模型名、公开价格、上下文能力、推理强度与可路由状态；请求示例始终使用 `<YOUR_ZMZAI_TOKEN>` 占位符，不输出渠道、上游地址或任何已配置 Key。`/models/[model]` 放置该模型的快捷示例，`/docs` 集中提供鉴权、非流式、流式、错误处理和 OpenAI SDK 接入说明。

## 用户工作面

用户工作面使用共享 Relay 壳层，侧栏按调用闭环排列：

1. **概览**：可用余额、近 30 天消费、调用量、成功率、最近请求、低余额提醒；
2. **模型**：与公开首页同一数据源，支持按模型查看价格、能力、推理强度和示例；
3. **API Keys**：创建、模型权限、每分钟限流、月消费上限、吊销和轮换；明文只在创建/轮换响应显示一次；
4. **用量**：按时间、模型、Token、状态筛选请求，展开查看 requestId、tokens、收费和安全错误摘要；
5. **账单**：余额、充值/调整流水、调用扣费和月度消费限制；金额由服务端返回；
6. **文档**：按模型生成 curl、OpenAI SDK 和流式请求示例。

用户看不到渠道成本、毛利、其他用户数据或上游 Key。用户用量 DTO 不返回渠道名称、`channelId`、上游模型、原始上游错误或网络错误；渠道尝试仅折叠为安全状态、总延迟和通用错误码。Token 不绑定渠道，由网关按模型映射、启用状态和优先级路由。

## 管理工作面

管理员工作面按运营动作排列：

1. **概览**：收入、已确认成本、待配置成本、毛利、异常、成功率、渠道健康；
2. **模型与价格**：维护 Sol、Terra、Luna 的公开状态、价格、上下文上限、最大输出和允许推理强度；
3. **渠道**：编辑地址、模型映射、成本、优先级、超时和启停；测试优先请求 `/models`，不支持时用已配置模型发最小 `chat/completions`；
4. **用户与余额**：搜索用户、查看余额与 Token、充值/扣款并填写审计理由；
5. **请求**：按时间、模型、用户、Token、状态查看调用，展开渠道尝试、延迟、错误和结算；
6. **账本**：收入、成本、余额调整、退款和审计记录。

运营端明确显示 `costStatus=unknown`，不把未知上游成本当作零成本或真实毛利。运营聚合按每次完成调用关联的 `ChannelAttempt.costStatus` 划分：已确认成本才进入成本与毛利计算；存在未知成本的调用单列为“待配置成本”，不进入真实毛利。

## 视觉与交互

沿用 `/Users/ulanxx/ulanxx_workspace/zmzai/zmzai-cloud/design.md` 的锁定系统：暖浆纸、暖墨、印泥红、Noto Serif SC、JetBrains Mono、锐利纸张边界和朱文方印署名。

Hallmark 选择：

- 首页宏结构：Catalogue；
- 首页导航：边缘对齐的产品导航，登录为明确的主动作；
- 首页内容：F3 Tabular Spec Sheet 为主，模型行统一节奏，不做图标方块卡；
- CTA：C3 Typographic Link 与印泥红主按钮；
- Footer：Ft1 Mast-headed；
- 动效：规则线/透明度的克制过渡，支持 reduced motion；
- 移动端：模型目录降为两列摘要或垂直规格列表，所有点击目标至少 44px，不产生横向滚动。

用户端和管理端优先信息密度与重复操作效率，不使用营销式 hero、嵌套卡片或虚构数据图表。

## 验收标准

- 未登录访问 `/` 能浏览三个模型的真实价格和能力，并能从页面进入登录、文档和模型详情；
- 已登录普通用户访问 `/` 进入 `/dashboard`，管理员进入 `/admin`；
- 用户端能从模型目录连续完成创建 Token、复制请求、查看调用和账单；
- 管理端能从概览连续进入模型、渠道、用户、请求和账本并完成运营写操作；
- 首页、用户端和管理端不出现 `gpt-4o`；
- 价格、余额、成本和用量均由服务端数据提供，不编造指标；
- 在 320、375、414、768px 宽度无横向溢出，导航、目录和表格可操作。
